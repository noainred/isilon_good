# 처음 시작하기 — 초보자 가이드

이 프로그램을 **처음 쓰는 분**을 위한 가장 짧은 길입니다. 설치부터 첫 결과까지 그대로
따라 하면 됩니다. 더 자세한 내용은 [사용 설명서(USER_GUIDE.md)](USER_GUIDE.md)에 있습니다.

> 한 줄 요약: **아이실론 같은 초대용량 NAS를 다른 리눅스 서버에 마운트해 두고, 웹페이지에서
> 폴더를 골라 "스캔 시작"만 누르면**, 프로그램이 **알아서 가장 빠른 방법을 찾아** 디렉터리별
> 용량·파일 수를 조사해 보여줍니다.

---

## 0. 이 프로그램이 하는 일

- 수천만~수십억 개 파일이 있는 NAS에서 **어느 디렉터리가 용량을 얼마나 쓰는지** 조사합니다.
- 트리 전체에 `du`를 한 번에 돌리면 메모리가 터져 죽는 문제를, **디렉터리 단위로 쪼개
  메모리를 거의 안 쓰고** 조사하도록 만들었습니다.
- 진행 상황·결과·서버 자원을 **웹 대시보드**로 실시간으로 봅니다.
- **추가 설치가 필요 없습니다** — 파이썬 3.6 이상만 있으면 표준 라이브러리만으로 돕니다.

---

## 1. 5분 체험 (실제 NAS 없이)

먼저 가짜 트리를 만들어 감을 잡아 봅니다.

```bash
# 1) 코드 받기
cd /opt
git clone https://github.com/noainred/isilon_good.git
cd isilon_good

# 2) 잘 설치됐는지 확인
python3 -m isilon_usage --version        # isilon_usage 1.x.x ...

# 3) 테스트용 가짜 트리 생성 (디렉터리 60개 / 파일 600개)
python3 -m isilon_usage gentest /tmp/demo --dirs 10 --subdirs 5 --files 10 --size 16K -y

# 4) 스캔 + 대시보드 실행
python3 -m isilon_usage run /tmp/demo --mount-base /tmp --port 8765
```

브라우저로 **http://<서버주소>:8765/** 에 접속하면 진행 상황과 결과가 보입니다.
`📊 분석 리포트` 탭도 눌러 보세요(파일 나이·소유자·확장자·최대 파일).

> 같은 화면을 원격에서 안전하게 보려면: `ssh -L 8765:127.0.0.1:8765 사용자@서버` 로 터널링.

## 2. 실제 NAS 조사하기 (권장 흐름)

### 2-1. NAS를 이 서버에 마운트

```bash
# 예시 (읽기 전용 권장 — 사고 방지)
mount -t nfs -o ro isilon:/ifs /mnt/isilon
```

### 2-2. 대시보드 실행 (스캔 가능 경로를 마운트로 제한)

```bash
python3 -m isilon_usage serve \
        --data-dir /var/lib/isilon_usage \
        --mount-base /mnt/isilon \
        --port 8765
```

- `--data-dir`: 조사 결과(DB)를 저장할 폴더. 한 번 정하면 계속 같은 걸 쓰세요(이력이 쌓입니다).
- `--mount-base`: **웹에서 스캔할 수 있는 경로를 이 안으로 제한**합니다(안전). 여러 NAS면
  `--mount-base`를 여러 번 주면 됩니다.

### 2-3. 웹에서 폴더를 고르고 시작

브라우저 **http://<서버>:8765/** → 맨 위 **「새 스캔 시작」**:

1. **마운트 빠른 선택** 또는 **폴더 탐색**으로 조사할 디렉터리를 찾아 클릭합니다.
2. **🔬 오토튜닝(최적 방법 자동)** 체크가 **기본으로 켜져** 있습니다 — 그대로 두세요.
3. **▶ 이 디렉터리 스캔 시작**.

### 2-4. 오토튜닝이 알아서 최적 방법을 찾습니다 ✨

시작을 누르면, 첫 화면에 **🔬 오토튜닝 카드**가 나타나 이렇게 동작합니다:

```
🔬 오토튜닝 — 이 경로에 가장 빠른 스캔 방법을 찾는 중
  방법                     처리량         배속
  단일(serial)            1,481 files/s   1.00배
  8프로세스               3,170 files/s   2.14배
  8프로세스 × 8스레드     12,318 files/s  8.32배   ◀ 가장 빠름
✅ 8프로세스 × 8스레드가 가장 빠릅니다 → 스캔 #3을 자동 시작했습니다.
```

- **단일 / 멀티프로세스 / 2단 병렬**을 각각 몇 초씩 **실제로 측정**해 비교합니다(읽기 전용).
- 가장 빠른 방법을 골라 **그 설정으로 본 스캔을 자동으로 시작**합니다.
- 왜 이렇게 하냐면 — NAS·영역마다 빠른 방법이 다르기 때문입니다(빠른 영역은 단일이, 느린
  고지연 영역은 프로세스×스레드 병렬이 몇 배 빠릅니다). **추측 대신 측정**해서 고릅니다.

> 끄고 싶으면 체크를 해제하고 시작하면, 아래 엔진(threads/pscan)·옵션을 직접 고른 대로 돕니다.

## 3. 결과 읽는 법

상단 탭으로 화면을 바꿉니다.

| 탭 | 무엇을 보나 |
|----|------------|
| **Summary** | 지금 진행 상황(어느 디렉터리 조사 중, 몇 %), 서버 메모리/CPU, **스캔 이력(회차별 소요 시간·결과)** |
| **디렉터리** | 디스크 사용량 **파이 차트**(클릭해서 더 깊이), **용량 상위 디렉터리** 표(정렬·드릴다운) |
| **추세·비교** | 같은 폴더를 여러 번 스캔하면 **증가 추세**와 **두 스캔 차이(diff)** |
| **📊 분석 리포트** | 파일 **나이(오래된=정리 후보)**, **소유자별**, **확장자별**, **최대 파일 Top**, **용량 소진 예측** |

핵심 숫자:
- **own_bytes(자기 용량)**: 그 폴더에 직접 든 파일들의 합.
- **total_bytes(재귀 용량)**: 하위 폴더까지 포함한 합 — 보통 이걸 봅니다.
- **확인된 사용량 %**: 지금까지 조사한 용량 ÷ 디스크 사용량(진행률 감 잡기용).

## 4. 자주 막히는 곳

| 증상 | 해결 |
|------|------|
| `python3: command not found` | 파이썬 3.6+ 설치 또는 `python` 으로 시도 |
| 브라우저 접속 안 됨 | `--host 0.0.0.0` 확인, 방화벽/포트 확인 |
| `Address already in use` | 다른 `--port` 사용 |
| "새 스캔 시작"에서 거부됨 | `--mount-base` 밖 경로임. 마운트 안쪽 경로를 고르세요 |
| 실행 후 `df`에 마운트가 잔뜩 생김 | **정상**(아이실론 자동 서브마운트). ⚠ `한 파일시스템(-x)`은 켜지 마세요(누락됨) |
| 화면이 멈춘 것 같음 | 거대 스캔에서 조회가 느려진 것(스캔은 살아있음). [멈춤 복구 문서](TROUBLESHOOTING-frozen-dashboard.md) |
| 중간에 멈췄다 | 데이터는 DB에 남습니다. 관리 표에서 **재개**, 또는 `resume <id>` |

> 멈춰도 안전합니다 — 모든 진행 상태가 DB에 저장되어, 같은 `--data-dir`로 다시 켜면
> 이어서 보거나 재개할 수 있습니다.
