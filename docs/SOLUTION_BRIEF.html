해결하는 문제

⚠ 기존 방식의 한계

  • du 한 방: 한 폴더에 파일 수천만 개면 메모리가 터져 프로세스가 죽습니다.
  • 단순 멀티스레드: 파이썬 GIL + 단일 락에 막혀 워커를 늘려도 1~2배에서 정체.
  • 6 PB 규모: 트리를 다 걸으면 며칠~몇 주. 진행 상황·병목이 보이지 않음.
  • 가시성 부재: 어느 디렉터리·사용자·파일이 공간을 먹는지 알기 어려움.

✓ 이 솔루션의 접근

  • 2단계 스캔: 디렉터리 단위로 쪼개 DB에 흘려보내 메모리를 일정하게.
  • 측정 기반 2단 병렬: 프로세스(GIL 우회)×스레드(지연 은닉)로 처리량 확장.
  • 오토튜닝: 영역마다 가장 빠른 방법을 실측해 자동 선택·시작.
  • 웹 대시보드: 진행·자원·드릴다운·분석 리포트를 실시간으로.
한눈에 보는 가치
추측이 아니라 측정
NAS는 영역·캐시 상태마다 빠른 방법이 다릅니다. 이 솔루션은 단일·멀티프로세스·2단 병렬을 실제로 재 보고 가장 빠른 설정으로 스캔합니다 — 그래서 빠른 영역은 낭비 없이, 느린 고지연 영역은 몇 배 빠르게 처리합니다.

핵심 기능
Memory-safe
🧠

메모리 최소 스캔

① 탐색(top-down)으로 디렉터리당 한 번만 훑어 DB에 기록 → 다음 목록도 메모리가 아닌 DB에. ② 상향식 집계로 재귀 용량 계산. 트리가 아무리 커도 메모리는 평탄(약 24MB).

Throughput
⚡

2단 병렬 엔진 (pscan)

프로세스로 GIL을 우회하고 프로세스당 스레드로 NFS 왕복 지연을 숨깁니다. 1단계 자식이 적은 영역은 적응형 깊이 분할로 병렬 단위를 자동 확보.

Auto
🔬

오토튜닝

새 스캔 시 단일·멀티프로세스·2단 병렬을 짧게 측정해 가장 빠른 방법을 자동 선택, 그 설정으로 본 스캔을 시작합니다. 측정 진행은 첫 화면에 실시간 표시.

Visibility
📊

웹 대시보드

웹에서 폴더를 골라 스캔 시작·중지·재개, 디스크 파이차트·드릴다운·검색, 진행률·서버 자원(메모리/CPU)·DB 생존 지표를 실시간으로.

Insight
📈

분석 리포트

파일 나이(콜드 데이터)·소유자·확장자별 사용량, 최대 파일 Top, 용량 소진 예측(90%/가득 참 예상일), 직전 대비 변화 Top.

Global
🌐

글로벌 통합 포탈

여러 데이터센터를 한 화면에 — 지역별 롤업, Cross-DC 경로 비교, 네트워크/인프라 모니터링. 저대역(20Mbps↓)에서도 요약만 받아 가볍게.

왜 이 솔루션인가

🔒 안전하고 가벼움

  • 표준 라이브러리만 — 폐쇄망 서버에 그대로 설치(Python 3.6+).
  • 읽기 전용 — 데이터를 변경하지 않음. mount도 ro 권장.
  • 작업 보호·로그인·감사 로그 — 보기는 자유, 작업엔 비밀번호.
  • MIT 라이선스 — 사내 자유 도입·확장.

💡 도입 효과

  • 정리 후보 식별 — 콜드 데이터·최대 파일·급증 디렉터리로 공간 회수.
  • 차지백 — 소유자·부서·유형별 사용량 가시화.
  • 용량 계획 — 추세 기반 가득 참 예상일로 선제 대응.
  • 글로벌 가시성 — 15개 DC를 한 화면에서 통합 관리.
